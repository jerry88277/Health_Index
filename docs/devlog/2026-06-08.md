## 13:07:57 +0800 — 選配② L4 block-bootstrap 控制限重構（merge aa4aeba / feat 725d704 / docs 354ded3）[verified]

### 背景與決策
使用者拍板「承擔 block-bootstrap 控制限重構」（②先前判為不可行）。高風險跨層改動 → worktree 隔離
（`worktree-l4-block-bootstrap`）、計畫→確認→執行、≥2 獨立紅隊複審後合併。

### 第一性原理診斷（verify-first，避免過度設計）
逐層分解「連續乾淨窗誤報」：**L1=1.0、L2=0.98（健康）、L4≈0.02–0.18（崩）** → **僅 L4 誤報**。
原框架「L2+L4 全面重構」過度設計；真因＝L4 的 iid null 對 golden PC1 自相關（ρ_1≈0.92）過敏。
通道實測：關係飄移（保邊際）由 **L2 SPE 殘差空間**抓（drift SPE 3.49 vs clean 1.62），**非 L4**。

### 變更摘要
- **drift.py**：自估區塊長度 ℓ（PC1 自相關連續 3-lag 落白噪帶；iid→1 統計等價，連續 TEP→~40）；
  `wasserstein_magnitude` 與 `mmd_pvalue` 改 **window-vs-window block-bootstrap**（ℓ>1）——null 抽連續窗
  反映窗級漫遊變異，乾淨連續窗不誤報、真分佈位移（B/C）仍抓。
- **health.py**：FWER `_fwer_drift_` 改 fit 於**保序全 golden**（L4 p 本即自校準），維 block-bootstrap 時序。
- **tep.py**：新增 `time_preserving` opt-in（連續不重抽，golden/clean/drift 取自 m1d00 不同連續段）；
  iid 預設不變。
- **config.py**：`drift_block_z=1.96`。

### 變更檔案

### Wisdom 雷區
- **iid null 對自相關過敏是 ② 不可行的真因**：window-vs-window（不是 vs-pool）是關鍵——vs-pool 在
  非平穩下對「300 樣本窗 vs 3000 樣本池均值」的自然差異過敏。wasserstein 與 mmd 皆須改 window-vs-window。
- **FWER split 洗牌會毀 block-bootstrap**：`gfit=G[perm[...]]` 打亂時序 → block_len_=1 → 退回 iid null
  → 連續乾淨窗誤報。L4 自校準故可 fit 全保序 golden（紅隊實測不致 FWER 膨脹）。
- **block-len 估計：首次穿越 vs 連續落帶**：非單調 ACF（AR(2) 振盪）會在某 lag 偶然近零 → 首次穿越
  低估 ℓ。改「連續 3-lag 落帶」+「lag-1 即不顯著則 ℓ=1」守 iid（19/20→1）。紅隊 A#2 修正。
- **偵測改由 L2、簡單融合 HI 不過閾**：時序情境下關係飄移是 L2 殘差訊號，融合 HI（權重稀釋）停在
  0.846，須靠 fwer_alarm（AC-6）抓。誠實 surface，非宣稱融合分數會明顯崩。
- **既有債（非本次引入）**：L2 permutation 在 in-sample 自相關窗略不保守（族系誤報~0.08）；held-out
  re-entry 窗受控 0.04–0.05。block-aware L2 列後續。

### Wisdom 雷區
- **d=0 的兩種來源不可混淆（Rule 12）**：synthetic 是 estimate_delay 真跑 R² argmax 得 0
  （X、Y 同潛變數、列對齊）；tep 預設稀疏標籤 common obs(29) < 2p+1(45) 低於可靠下限，回**保守
  fallback 0**（非 argmax 證得）。紅隊抓到原 docstring 把 fallback 講成「估計確認無延遲」，已修正。
- **使用者原想要的「2h 物理延遲」在此半合成、列對齊資料上無法復原**——與選配②同根因（iid 重抽/同時刻
  取樣移除時間結構）。誠實 surface，不偽造；對齊機制備妥，真實有延遲產線插入即估出 d>0 並校正。
- **in-sample 殘差會說謊**：GPR(RBF) 會把無關的 naive 對 overfit 到低 in-sample 殘差（naive 0.11 <
  aligned 0.22）。唯**留出集**揭穿錯位映射（naive 退化為預測均值）。WHY 測試改用留出集。
- **預測路徑 d>0 latent 不一致**：訓練 f:X(t−d)→Y(t) 但端點預測 Ŷ(t)=f(X(t))，d>0 時實際估的是
  Y(t+d)。目前 d=0 不觸發，已於 docstring 標記，未來真實延遲資料須對齊預測域。
